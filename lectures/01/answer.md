## 宿題

- 取り組んだレベル：実装
- やったこと：
  - `app/ask.py` に `--chat` オプションを追加し、会話履歴を保ったまま続けて質問できるようにした。
    ```bash
    uv run python -m app.ask --chat "LoRAとは何ですか？"
    ```
    空行か `exit` で終了する。
  - LLM の API 自体は前のやり取りを覚えていない。そこで `Conversation` クラスがこれまでの質問（`role="user"`）と回答（`role="model"`）を `types.Content` のリストとして持ち、毎回「履歴＋新しい質問」をまとめて `generate_content` の `contents` に渡すようにした。SDK の `client.chats` を使えば同じことができるが、履歴がどう送られているかを自分で確かめるため、あえて手で書いた。
  - API エラー（429 のレート制限など）で失敗した質問は履歴に入れないようにした。失敗しても会話は終わらず、それまでの履歴を保ったまま続けられる。
  - API を呼ばない偽クライアントを使ったテスト `tests/test_ask.py` を追加した。「2回目のリクエストに1回目の質問と回答が入っているか」と「失敗した質問が履歴に残らないか」を、APIキーや無料枠を使わずに確かめられる。`uv run pytest -q` で 14 passed。
- 結果：

  | 往復 | 質問 | 入力トークン | 出力トークン | 回答 |
  |---|---|---|---|---|
  | 1 | LoRAとは何ですか？ | 7 | 599 | Low-Rank Adaptation の説明 |
  | 2 | それをさらに省メモリにした手法は？ | 615 | 784 | 「それ」を LoRA と解釈し、QLoRA・DoRA・AdaLoRA・PiSSA を紹介 |
  | 3 | 最初に私が聞いた手法の名前は何でしたか？ | 1409 | 16 | 「最初にあなたが聞いた手法の名前は『LoRA（ローラ）』です！」 |

  - 2往復目で「それ」が LoRA を指すと理解し、3往復目では2つ前の質問を正しく答えられた。前の会話が文脈として伝わっている。
  - 入力トークンは 7 → 615 → 1409 と増えた。615 ≒ 7 ＋ 599 ＋ 新しい質問、1409 ≒ 615 ＋ 784 ＋ 新しい質問で、履歴を毎回丸ごと送っていることが数字でも確認できた。
  - 3往復目は出力が 16 トークンしかないのに、入力は 1409 トークンかかっている。短い質問でも、それまでの会話が長いとコストが大きくなる。
- 気づき・疑問：
  - 会話が続くほど、過去の回答ぶんだけ入力トークンが毎回増えていく。今回は回答が長い（600〜800トークン）ので、数往復で入力が数千トークンになる。長い会話では古い履歴を削る・要約するなどの工夫が要りそう。トークン単位の課金や上限がある場合は特に効いてくると思う。
  - 2往復目の回答には、DoRA の説明が「大きさ（方向）」と「方向（大きさ）」で入れ替わって矛盾していたり、読み仮名が「ドー拉」と崩れていたり、PiSSA の正式名称が怪しかったりと、細部の誤りがあった。一般的な用語でも、細かいところは確信を持って間違えることがある。
